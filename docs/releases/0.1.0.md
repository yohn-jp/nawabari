# nawabari 0.1.0

## Summary

First public release of Nawabari. This release completes the pre-publication
rename from GitPaw, ships the local Git session lifecycle CLI as
`nawabari@0.1.0`, and exposes the same entry point through Git's
`git nawabari` external-subcommand discovery.

## Highlights

- **Canonical CLI identity**: the `nawabari` executable is the primary entry
  point, and `git-nawabari` provides the equivalent `git nawabari` invocation.
- **Session lifecycle**: repository-scoped session registration, provisioning,
  guard checks, and safe close/cleanup are available through the CLI.
- **Unified registry locking**: session and generic registry mutations use the
  same repository lock authority, including coordinated stale-lock reclaim.
- **Safe cleanup**: Git-ignored generated artifacts such as `node_modules`,
  `dist`, and caches do not by themselves make a worktree dirty, while tracked
  changes and non-ignored recoverable files continue to block destructive
  cleanup.
- **Release validation**: the exact `npm pack` tarball is built, inspected,
  installed in an isolated consumer, and smoke-tested before publication.

## Fixed

- Closed the stale-lock reclaim race so a concurrent reclaimer cannot remove a
  lock acquired after the final ownership check.
- Made synchronous lock metadata publication atomic and failed closed on npm
  namespace lookup errors before any publish mutation.
- Made stale reclaim-marker cleanup tolerate concurrent `ENOENT` while
  preserving typed failures for other I/O errors.
- Made the stale-lock fixture independent of the host process PID.
- Added coverage for non-default registry directory overrides and for
  non-ignored recoverable files blocking destructive cleanup.
- Documented both package entry-point names and their shared implementation.

## Behavioral changes

- The product and package identity is now Nawabari; `nawabari` is the
  canonical command name.
- GitPaw, `git-paw`, and `git paw` compatibility aliases are intentionally not
  provided because the product was unpublished before this release.
- The supported Node.js range is `>=22.13 <25`.

## Upgrade instructions

Install the published package globally:

```bash
npm install -g nawabari@0.1.0
```

Or run it without a global install:

```bash
npx -y nawabari@0.1.0 --version
```

No configuration migration is required for this first public release.

## Breaking changes

None for previously published users. GitPaw-to-Nawabari is a pre-publication
rename, so old unpublished product names are not supported.

## Known limitations

- Resource claims, path-aware authorization, and synchronization coordination
  are deferred to post-0.1.0 work.
- The session registry and worktree lifecycle are local repository facilities;
  this release does not provide remote coordination or OS-level sandboxing.
