# Nawabari 0.11.0

Nawabari 0.11.0 introduces working sets as a first-class session concept — a repository-local, revisioned expansion of a session's effective scope — and makes their enforcement authoritative across bootstrap, verification, and protected execution.

## Highlights

- Adds repository-local auxiliary-state projection as the persisted home for working-set and related session extensions.
- Adds atomic initial claims on session creation, later exposed as retry-safe on the public `session create` path.
- Adds lifecycle reconciliation apply, integrating auxiliary state with the managed-worktree lifecycle.
- Adds effective working-set composition and revisioned working-set expansion over the claimed-resource baseline.
- Enforces the working-set runtime boundary at session bootstrap and wires it into protected execution.
- Isolates verification execution authority and enforces a read-only runtime boundary for verification.
- Aligns stale lifecycle recovery actions with the new auxiliary-state and working-set authorities.
- Projects the Landlock runtime adapter into strict FHS sessions.

## Working sets

A working set is a revisioned, repository-local expansion of a session's effective scope beyond its claimed resources. It is composed deterministically from claims plus recorded expansions, persisted through the repository-local auxiliary-state projection, and reconciled through the managed-worktree lifecycle rather than mutated ad hoc.

Working-set membership is enforced as a runtime boundary at session bootstrap and inside protected execution: operations outside the effective working set are rejected rather than silently widened.

## Verification execution authority

Verification execution is now isolated from other protected execution and runs under an explicit read-only runtime boundary, so verification cannot itself mutate session or working-set state.

## Compatibility

This is a pre-1.0 minor release. No registry or persisted-session migration is required. Existing supported CLI flows remain available; working sets extend claimed-resource scope rather than replacing it.

Node.js 24 or newer remains required. Protected session execution remains Linux-only and fail-closed when required sandbox primitives are unavailable.

## Upgrade

```bash
npm install -g nawabari@0.11.0
npx -y nawabari@0.11.0 --version --json
```
