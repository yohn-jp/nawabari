# Nawabari 0.8.0

Nawabari 0.8.0 completes the protected standalone execution and resource-ownership work built on top of 0.7.x, and raises the supported runtime baseline to Node.js 24+.

## Highlights

- Finalizes the versioned standalone execution and resource-claim machine contracts used by the public CLI and packed package flows.
- Hardens protected execution on Linux with fail-closed sandbox requirements, including namespace isolation, seccomp baseline enforcement, capability reduction, and optional Landlock/cgroups defense in depth.
- Proves exact packed-package standalone execution from the release tarball rather than from repository-local sources.
- Adds the external/preselected-UID handoff contract used by Mottainai while keeping Nawabari authoritative for local Git/session/resource ownership.
- Strengthens deterministic cgroup scope handling, seccomp architecture mappings, ambient Git-environment authority handling, diagnostics, and compatibility evidence.
- Raises the supported Node.js runtime baseline to `>=24` and makes `package.json#engines.node` the runtime-policy authority used by doctor and CI.

## Compatibility

This is a pre-1.0 minor release. Node.js 22 and 23 are no longer supported; upgrade to Node.js 24 or newer before installing Nawabari 0.8.0.

Nawabari remains a standalone local Git/session authority. Mottainai integration is an external handoff boundary only and does not transfer session, worktree, resource, or local-Git authority away from Nawabari.

Protected session execution remains Linux-only and fail-closed when required sandbox primitives are unavailable.

## Upgrade

```bash
npm install -g nawabari@0.8.0
npx -y nawabari@0.8.0 --version --json
npx -y nawabari@0.8.0 capabilities --json
npx -y nawabari@0.8.0 doctor --json
```

## Release verification

The release path verifies the immutable `v0.8.0` tag against `package.json`, builds and validates the exact publish tarball, smoke-tests that same artifact on Node.js 24, and publishes it through npm Trusted Publishing/OIDC.
