# Nawabari 0.9.2

Nawabari 0.9.2 republishes 0.9.0 after fixing a release-notes formatting issue and a smoke-test dependency-install gap that both blocked the publish pipeline. There is no functional change beyond 0.9.0.

## Highlights

0.9.2 carries the same functional content as 0.9.0:

- Makes the XState v5 Session lifecycle machine the executable authority for public Session transition semantics.
- Preserves guard-dependent lifecycle behavior in public projections, including accepted and rejected `gc` outcomes.
- Adds stable package entry points for `nawabari/state`, `nawabari/contract`, and `nawabari/manifest` without exposing internal XState state-node ids, context, snapshots, or deep imports.
- Adds the versioned Nawabari Product State Manifest as a deterministic public projection for composition, tooling, and documentation consumers.
- Keeps Resource Claim exact-resource transition semantics on the dedicated pure transition matrix authority rather than duplicating them in XState.
- Improves CLI discovery by exposing the authoritative operation vocabulary in command help and machine-readable command metadata.
- Adds explicit `--all-claimed` resource selection for governed `commit` and `push` flows while retaining existing authorization and fail-closed claim checks.
- Adds read-only `session discard --preview` so destructive scope, recoverable work, claims, and reconciliation blockers can be inspected before discard.

## Fix

- Reformats `docs/releases/0.9.0.md` with Prettier. The unformatted file failed the `publish.yml` Format check job, which blocked the `v0.9.0` tag from ever completing the publish pipeline.
- Installs dependencies in the `publish.yml` smoke-test job before invoking `scripts/smoke-test.mjs`. The job previously checked out the repo and downloaded the tarball without running `pnpm install`, so `scripts/seed-offline-runtime-dependencies.mjs` could not find `node_modules/xstate` (a runtime dependency since #260) and threw before the tarball was ever smoke tested (#282).

No `nawabari@0.9.0` or `nawabari@0.9.1` package was ever published to npm. `v0.9.0` and `v0.9.1` as git tags and GitHub Releases have been removed; GitHub does not allow reusing a tag name that was once an immutable release, which is why this release is numbered 0.9.2 rather than retrying 0.9.0 or 0.9.1. 0.9.2 is the first published release carrying this content.

## Compatibility

This is a pre-1.0 minor-content, patch-numbered release. No registry or persisted-session migration is required, and existing supported CLI flows remain available.

Node.js 24 or newer remains required. Protected session execution remains Linux-only and fail-closed when required sandbox primitives are unavailable.

## Upgrade

```bash
npm install -g nawabari@0.9.2
npx -y nawabari@0.9.2 --version --json
npx -y nawabari@0.9.2 capabilities --json
npx -y nawabari@0.9.2 doctor --json
```

## Release verification

The release path verifies the immutable `v0.9.2` tag against `package.json`, builds and validates the exact publish tarball, smoke-tests that same artifact on Node.js 24, verifies the stable public package entry points from the packed install, and publishes through npm Trusted Publishing/OIDC.
