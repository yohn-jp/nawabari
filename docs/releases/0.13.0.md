# Nawabari 0.13.0

Nawabari 0.13.0 consolidates the current local runtime, isolation, coordination, observability, and control surfaces before the next architecture-refactoring cycle.

## Highlights

- Adds the machine-local Nawabari Control Server and built-in Web UI through `nawabari server`.
- One loopback-only Control Server can inspect multiple locally known Nawabari repositories while each repository retains independent canonical authority.
- Exposes canonical repository runtime snapshots and typed lifecycle actions without making the existing CLI or TUI depend on the server.
- Includes the completed worktree runtime-profile, filesystem-authority, local-runtime, bounded working-set, lifecycle/reconciliation, resource-coordination, and runtime-observability work integrated since 0.12.2.
- Preserves fail-closed protected execution and existing repository/session authority semantics.

## Control Server

```bash
nawabari server
```

The server listens on `127.0.0.1:47471` by default and provides the built-in local Web UI. It is machine-local by contract: the bind address is not configurable, and existing CLI/TUI operation remains independent of the server.

## Compatibility

Node.js 24 or newer remains required. Protected session execution remains Linux-only and fail-closed when required sandbox/runtime capabilities are unavailable.

The Control Server is optional. Existing CLI commands and the terminal UI continue to operate directly against canonical Nawabari authorities.

## Upgrade

```bash
npm install -g nawabari@0.13.0
npx -y nawabari@0.13.0 --version --json
```
