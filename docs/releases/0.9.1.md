# Nawabari 0.9.1

Nawabari 0.9.1 republishes 0.9.0 after fixing a release-notes formatting issue that blocked the publish pipeline. There is no functional change beyond 0.9.0.

## Highlights

0.9.1 carries the same functional content as 0.9.0:

- Makes the XState v5 Session lifecycle machine the executable authority for public Session transition semantics.
- Preserves guard-dependent lifecycle behavior in public projections, including accepted and rejected `gc` outcomes.
- Adds stable package entry points for `nawabari/state`, `nawabari/contract`, and `nawabari/manifest` without exposing internal XState state-node ids, context, snapshots, or deep imports.
- Adds the versioned Nawabari Product State Manifest as a deterministic public projection for composition, tooling, and documentation consumers.
- Keeps Resource Claim exact-resource transition semantics on the dedicated pure transition matrix authority rather than duplicating them in XState.
- Improves CLI discovery by exposing the authoritative operation vocabulary in command help and machine-readable command metadata.
- Adds explicit `--all-claimed` resource selection for governed `commit` and `push` flows while retaining existing authorization and fail-closed claim checks.
- Adds read-only `session discard --preview` so destructive scope, recoverable work, claims, and reconciliation blockers can be inspected before discard.

## Fix

- Reformats `docs/releases/0.9.0.md` with Prettier. The unformatted file failed the `publish.yml` Format check job, which blocked the `v0.9.0` tag from ever completing the publish pipeline; no `nawabari@0.9.0` package was ever published to npm. `v0.9.0` as a git tag and GitHub Release has been removed; 0.9.1 is the first published release carrying this content.

## Compatibility

This is a pre-1.0 minor-content, patch-numbered release. No registry or persisted-session migration is required, and existing supported CLI flows remain available.

Node.js 24 or newer remains required. Protected session execution remains Linux-only and fail-closed when required sandbox primitives are unavailable.

## Upgrade

```bash
npm install -g nawabari@0.9.1
npx -y nawabari@0.9.1 --version --json
npx -y nawabari@0.9.1 capabilities --json
npx -y nawabari@0.9.1 doctor --json
```

## Release verification

The release path verifies the immutable `v0.9.1` tag against `package.json`, builds and validates the exact publish tarball, smoke-tests that same artifact on Node.js 24, verifies the stable public package entry points from the packed install, and publishes through npm Trusted Publishing/OIDC.
