# nawabari 0.6.0

## Summary

Nawabari 0.6.0 makes session cleanup explicitly recoverable for intentionally abandoned work and hardens the non-ancestry integration proof used by safe close. It introduces a supported `session discard` lifecycle, consistent explicit session targeting, stronger bounded diagnostics, and preserves Nawabari as the sole local Git/session authority.

## Highlights

- `session discard --session <id>` provides an explicit, typed, auditable path for intentionally disposable sessions. It removes only the selected owned worktree/branch, releases only that session's claims, and never acts as an implicit fallback from `close`, `gc`, `doctor`, or reconciliation.
- Discard is retryable across partial failure. Nawabari persists `terminal_operation: "discard"` and the pre-discard HEAD before destructive mutation so interrupted cleanup can converge safely on retry.
- Session-scoped lifecycle commands now expose a consistent explicit targeting grammar. `--session <id>` remains canonical, with an unambiguous positional session-id alias where supported; supplying both forms is rejected.
- `session close --integrated-revision` now rejects self-referential, sibling, and detached-equivalent revisions unless the supplied revision is anchored to the authoritative integration lineage. Lineage/authority proof is separated from tree/content equivalence evidence.
- Close/inspect diagnostics expose bounded current-session HEAD, resolved integration revision, lineage/authority proof, content proof, and safe recovery actions, including explicit discard only when the user intentionally chooses to abandon the work.
- Packed CLI regressions cover stale/intermediate executions whose final merged PR head differs from the residual session head: ordinary close remains protected while explicit discard safely releases the obsolete session.

## Compatibility

This is a pre-1.0 minor release because it adds a new public lifecycle command and additive machine-contract fields. Existing ordinary ancestry-based close behavior remains unchanged, and the 0.5.x integration-proof path remains available with stronger authority validation.

No migration is required for existing session state. New terminal fields are additive and are only present for sessions explicitly discarded by 0.6.0 or later.

Nawabari remains standalone and local: it does not trust GitHub or another orchestrator as cleanup authority. Integration evidence is independently verified against local Git history, and destructive discard requires an explicit selected session.

## Upgrade

```bash
npm install -g nawabari@0.6.0
npx -y nawabari@0.6.0 --version --json
npx -y nawabari@0.6.0 capabilities --json
npx -y nawabari@0.6.0 session discard --help --json
```

## Release scope

Includes the integration-proof authority hardening from #139 / PR #140 and the explicit obsolete-session discard/recovery lifecycle from #138 / PR #141 since 0.5.0.
