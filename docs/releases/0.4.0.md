# nawabari 0.4.0

## Summary

This release adds opt-in protected Linux session execution and strengthens
Nawabari's standalone machine contract with atomic complete-set resource-claim
replacement and outcome-aware registry durability.

## Highlights

- **Protected Linux session execution** (#86, #100): Nawabari now exposes the
  versioned `nawabari.sandbox-execution.v1` contract and `session run` /
  `session exec` entry points. On supported Linux hosts, protected execution is
  compiled into a fixed, argv-safe bubblewrap topology bound to the existing
  Nawabari session authority. Required capabilities fail closed when
  unavailable; there is no silent unsandboxed fallback.
- **Explicit sandbox boundaries** (#86, #100): protected execution isolates the
  owned worktree and private runtime state with fixed namespace/mount policy
  and dropped capabilities. Network mode remains explicitly inherited, and
  Landlock, cgroups, seccomp policy, OCI/VM support, and per-session OS users
  are not claimed by this release.
- **Atomic complete-set claim replacement** (#101, #106): `session update` and
  `resource update` accept repeated adjacent `--resource` / `--mode` pairs and
  replace the complete desired claim set through one `updateClaims()`
  transaction. Rejected updates leave the previous persisted claim set intact,
  and retries of an unchanged desired set are idempotent. The surface is
  discoverable through `capabilities --json` as `claim_set_replacement`.
- **Fail-closed claim parsing** (#101, #106): `session claim` and
  `resource claim` now accept exactly one resource/mode pair instead of
  silently collapsing repeated pairs to the last value. Ambiguous or
  interleaved pair syntax is rejected before reaching the mutation backend.
- **Outcome-aware registry durability** (#102, #105): session/claim registry
  persistence now shares one atomic-write/fsync policy. Failures observed after
  rename surface as `REGISTRY_DURABILITY_UNCERTAIN`; compound provisioning
  reconciles visible authoritative state and does not destructively roll back
  physical resources unless absence of the registry effect is proven.
- **Deterministic release baseline** (#113, #114): required sandbox-launcher
  contract tests no longer depend on undeclared ambient bubblewrap availability
  in the GitHub Actions runner. Controlled test capability is explicitly
  provisioned for logic/contract coverage, while tests that claim real
  isolation still require genuine bubblewrap. Production fail-closed behavior
  is unchanged.

## Compatibility and migration

No migration is required for existing 0.3.0 session or registry state.
Protected Linux execution is opt-in; existing session lifecycle behavior
remains available as before.

The stricter single-pair `claim` parsing is intentional correctness hardening.
Callers that need to replace multiple claims atomically should use
`session update` or `resource update` with the complete desired set.

## Upgrade

```bash
npm install -g nawabari@0.4.0
npx -y nawabari@0.4.0 --version --json
npx -y nawabari@0.4.0 capabilities --json
```

Mottainai should consume Nawabari's atomic claim-set replacement and current
standalone execution authority directly rather than emulate release/reclaim
transactions in the caller.
