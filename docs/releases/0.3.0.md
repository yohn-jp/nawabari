# nawabari 0.3.0

## Summary

This release strengthens Nawabari's standalone execution authority with exact,
fail-closed evidence, distinct resource-claim mode semantics, centralized Git
observation primitives, and hardened agent-facing diagnostics.

## Highlights

- **Distinct resource claim modes** (#62/#69): one normative resource-claim
  model with explicit read, write, and exclusive-write semantics across
  acquisition and operation authorization, including persisted-schema
  migration.
- **Exact, fail-closed evidence** (#64): checkpoint and commit results now
  describe the actual Git-observed state exactly; a path that cannot be
  represented safely fails the checkpoint closed with `GIT_STATE_AMBIGUOUS`
  instead of silently disappearing from evidence.
- **Centralized Git observation** (#66): bounded, NUL-safe Git path
  observation and canonicalization now live in one shared module, used by
  checkpoint, governed mutation, and commit path consumers alike.
- **Push inspection bound to remote generation** (#67): governed push
  inspection and mutation are bound to one observed remote branch generation,
  fetching missing ancestry only for the explicit target branch into a
  disposable ref and pushing with an exact remote lease.
- **Bounded read-only repository evidence** (#68): deterministic, bounded
  repository evidence is now exposed for explicitly owned Nawabari sessions.
- **Hardened agent-facing CLI diagnostics** (#55): `INSUFFICIENT_CLAIM_MODE`
  is distinguished from `MISSING_RESOURCE_CLAIM`, command-specific
  human/JSON help is generated from one command specification, and
  `managed_worktree_root` is exposed through repository status.
- **Bounded output budgets** (#54): default `status` and `session list`
  results are bounded, with explicit `--history`/`--all` paging and
  deterministic continuation metadata; failure diagnostics keep full
  in-process detail with explicit truncation metadata at the CLI boundary.
- **Caller-declared commit-message validation** (#59): `nawabari commit`
  gains an optional `--message-pattern <regex>`; a non-matching (or invalid)
  pattern fails the commit closed with `INVALID_COMMIT_MESSAGE` before
  anything is staged.
- **Faster worktree installs** (#56): repeated `pnpm` worktree installs are
  optimized based on the fresh-worktree install experiment (#44).

## Upgrade

```bash
npm install -g nawabari@0.3.0
npx -y nawabari@0.3.0 capabilities --json
```

Mottainai remains an optional orchestrator. It must consume this standalone
contract rather than maintain a duplicate local execution authority.
