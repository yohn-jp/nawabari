# Nawabari 0.12.0

Nawabari 0.12.0 completes the repository-governed local runtime architecture and its canonical observability surface.

## Highlights

- Completes multi-session resource coordination, atomic handoff, conflict preview, and deterministic coordination evidence.
- Adds canonical runtime profiles, profile pinning, drift inspection, and managed runtime materialization.
- Completes governed filesystem policy and file-operation authority, including durable receipts and reconciliation.
- Completes the worktree-local protected runtime with durable execution ownership, delegated cgroups v2, drain/finalization, and fail-closed lifecycle integration.
- Adds the transport-neutral Repository Runtime Snapshot, bounded agent status, attention/reconciliation projections, and human runtime views.
- Adds bounded lifecycle/execution history with provenance while keeping history strictly non-authorizing.
- Strengthens composed Linux/Nix/package certification across the complete runtime path.

## Runtime authority

Session lifecycle, SessionRegistry, ResourceClaim, filesystem policy, execution ownership, and reconciliation remain the canonical mutation authorities. The new observability surfaces compose those authorities rather than creating a parallel state model.

Protected execution remains fail-closed: missing runtime material, stale admission/epoch evidence, unverifiable process ownership, or incomplete lifecycle evidence does not become permission.

## Repository observability

Repository Runtime Snapshot now provides one bounded read model for session, coordination, profile, filesystem, process, lifecycle, reconciliation, and history evidence.

Lifecycle/execution history is persisted with authoritative registry mutations, retains provenance and explicit bounded coverage, and is never used to authorize cleanup, replay, ownership recovery, or lifecycle mutation.

## Compatibility

This is a pre-1.0 minor release. Existing supported CLI flows remain available. Persisted runtime features are version-gated and fail closed when unsupported.

Node.js 24 or newer remains required. Protected session execution remains Linux-only and requires the supported sandbox/runtime capabilities.

## Upgrade

```bash
npm install -g nawabari@0.12.0
npx -y nawabari@0.12.0 --version --json
```

## Release verification

The release path verifies the immutable `v0.12.0` tag against `package.json`, builds and validates the exact publish tarball, exercises the packed product and supported Linux system E2E path, and publishes through npm Trusted Publishing/OIDC.
