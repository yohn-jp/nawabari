# Nawabari 0.15.0

Nawabari 0.15.0 adds session-bound verification and owner-staged Candidate bundles, narrows strict sandbox procfs visibility for masked rootless OCI environments, and refreshes development and release dependencies.

## Highlights

- Exposes session verification snapshots, Candidate path discovery, and bounded verification through the CLI and the public `nawabari/contract` exports.
- Imports exact Git Candidate bundles into private, session-owned scratch and verifies their commit/tree identities before read-only verification.
- Binds verification results to fresh session policy, source observations, managed execution identity, bounded raw output, physical observations, and a canonical receipt.
- Adds explicit termination of a session's owned execution scopes through `session close --drain-policy terminate`, preserving sibling sessions and existing close requirements.
- Selects an empty read-only `/proc` view when a masked parent procfs prevents a new private procfs, while preserving strict namespace and filesystem restrictions.
- Updates Node type definitions, ESLint, gh-inari, Prettier, tsx, typescript-eslint, pnpm, and the pinned setup-node/upload-artifact/download-artifact Actions.

## Session-bound verification

The CLI exposes `verification snapshot`, `verification candidate-paths`, and `verification execute`. The public contract exports the corresponding snapshot, Candidate path/staging, and execution operations. Requests require an active managed session and its exact fresh owner snapshot; stale policy or claims, missing ownership, and unavailable tracking fail closed.

Candidate transfers use owner-private paths and bounded regular files. Staging verifies the bundle digest and exact advertised Git source before importing it into owned scratch. Verification receives a read-only Candidate projection; declared reads remain confined to the selected visibility. Scratch release requires the existing ownership, clean-source, and drained-execution checks.

See [session-bound verification](../reference/session-bound-verification.md) for request schemas, command examples, and result semantics.

## Strict execution in rootless OCI environments

The launcher observes the parent procfs topology before selecting its strict `/proc` view. A masked/overmounted parent procfs in an unprivileged user namespace, or an unobservable parent procfs, selects an empty read-only tmpfs. Ordinary observable host topologies retain a new private procfs. The launcher does not expose the enclosing procfs or broaden permissions after a failed launch.

The denied procfs view has no `/proc/self`, process enumeration, or proc-based descriptor paths. Programs requiring those interfaces may fail. Managed execution still requires observable namespace isolation, supported sandbox/runtime material, and owned process tracking; this change does not supply cgroup delegation.

See [procfs selection](../reference/rootless-oci-procfs.md) and the [scoped local OCI evidence](../reference/oci-local-verification-20261017.md). That evidence belongs to the recorded candidate and environment, not the 0.15.0 release artifact. It retains an unresolved cancellation acknowledgement and does not claim a complete cancellation receipt or full Linux-system certification.

## Dependency compatibility

ESLint advances to 10.12.0; 10.13.0 is excluded because it does not yet satisfy pnpm's minimum release age at preparation time. The supply-chain policy remains enabled.

TypeScript remains at 6.0.3 because typescript-eslint 8.71.2 supports TypeScript `>=4.8.4 <6.1.0`; upgrading to TypeScript 7 would leave the supported parser/compiler combination. XState remains at 5.33.2, the current stable release at preparation time.

The package manager is pinned to pnpm 12.14.0, with matching local CI/release setup versions. The obsolete release-age exception for gh-inari 0.13.2 is removed. gh-inari ships prebuilt artifacts, so its source-worktree preinstall is explicitly disabled in pnpm's build policy. Updating the installed gh-inari development package does not lift the organization suspension on agent Inari usage or change organization-owned workflows.

## Compatibility and upgrade

Node.js 24 or newer remains required. Protected execution remains Linux-only and refuses launch when required enforcement or ownership evidence is unavailable. The Control Server remains optional and machine-local. Existing registry and public lifecycle compatibility rules remain in force.

After publication:

```bash
npm install -g nawabari@0.15.0
npx -y nawabari@0.15.0 --version --json
```
