# Nawabari 0.9.0

Nawabari 0.9.0 makes the Session lifecycle executable state model authoritative through XState v5 and exposes stable public state, contract, and Product State Manifest package surfaces derived from that authority.

## Highlights

- Makes the XState v5 Session lifecycle machine the executable authority for public Session transition semantics.
- Preserves guard-dependent lifecycle behavior in public projections, including accepted and rejected `gc` outcomes.
- Adds stable package entry points for `nawabari/state`, `nawabari/contract`, and `nawabari/manifest` without exposing internal XState state-node ids, context, snapshots, or deep imports.
- Adds the versioned Nawabari Product State Manifest as a deterministic public projection for composition, tooling, and documentation consumers.
- Keeps Resource Claim exact-resource transition semantics on the dedicated pure transition matrix authority rather than duplicating them in XState.
- Improves CLI discovery by exposing the authoritative operation vocabulary in command help and machine-readable command metadata.
- Adds explicit `--all-claimed` resource selection for governed `commit` and `push` flows while retaining existing authorization and fail-closed claim checks.
- Adds read-only `session discard --preview` so destructive scope, recoverable work, claims, and reconciliation blockers can be inspected before discard.

## Public state and contract surfaces

The supported package-level state interfaces are now available through stable exports:

```js
import {
  classifyNawabariState,
  nawabariTransitionDecision,
} from "nawabari/state";

import { machineContract } from "nawabari/contract";

import {
  generateNawabariProductStateManifest,
  nawabariProductStateManifest,
} from "nawabari/manifest";
```

These exports are projections of Nawabari's implementation-owned authorities. Consumers must not depend on internal XState modules, state-node ids, actor references, machine context, snapshots, or `dist/` deep imports.

## Session lifecycle authority

The Session lifecycle machine is authoritative for executable lifecycle policy. Public state and machine-contract projections preserve policy-relevant metadata such as allowed/rejected outcomes, public targets, reasons, authority identifiers, and explicit-intent requirements.

Guarded transitions remain guarded in the projection. For example, `close-ready` plus `gc` can either transition to `closed` when the destructive-age guard accepts or remain a rejected public transition with the corresponding reason when it rejects.

The Product State Manifest is downstream of these authorities and is not an editable policy source.

## Resource Claim authority

Resource Claim exact-resource lifecycle semantics intentionally remain a pure total transition matrix over the current and requested claim modes. This keeps the exact claim transition classifier small, deterministic, and independent from Session lifecycle orchestration.

Compatibility checks, path overlap/conflict analysis, operation-required access, and mutation authorization remain separate authorities and are not folded into the transition matrix.

## CLI additions

`authorize` and `guard` expose the authoritative operation vocabulary through command discovery rather than maintaining an independent handwritten list.

`commit` and `push` accept `--all-claimed` as an explicit selector. It is mutually exclusive with explicit `--resource` selection. Selected resources still pass through the existing mutation-authorization authority; the selector does not create a second authorization path.

`session discard --preview` is observation-only. It reports the current/persisted/physical Session state, worktree and branch presence, recoverable commits, uncommitted work, bounded claim evidence, destructive scope, and diagnostic blockers without invoking cleanup or mutation.

## Compatibility

This is a pre-1.0 minor release. No registry or persisted-session migration is required, and existing supported CLI flows remain available.

Node.js 24 or newer remains required. Protected session execution remains Linux-only and fail-closed when required sandbox primitives are unavailable.

Consumers adopting the new public package surfaces should use only the documented stable exports.

## Upgrade

```bash
npm install -g nawabari@0.9.0
npx -y nawabari@0.9.0 --version --json
npx -y nawabari@0.9.0 capabilities --json
npx -y nawabari@0.9.0 doctor --json
```
