# Nawabari 0.14.0

Nawabari 0.14.0 publishes the completed NAWABARI-TA-1 architecture convergence and the new session lifecycle, runtime observation, verification provenance, and hardened local Control surfaces integrated since 0.13.0.

## Highlights

- Converges the implementation onto the documented target architecture, with explicit product, state/authority, session lifecycle, runtime-process, filesystem-isolation, resource-coordination, persistence/concurrency, control-surface, and verification-provenance boundaries.
- Adds canonical session parking and resume semantics, persisted retention intents, public park/resume actions, and v2 contract discovery.
- Adds repository runtime observation across coordination, processes, profiles, filesystem state, lifecycle state, and a composed repository observation service.
- Adds exact-source verification provenance, including packed public-consumer proof.
- Hardens the machine-local Control Server with singleton leasing, serialized repository catalog registration, isolated repository waits, trusted local capability handling, and no-follow endpoint-locator reads.
- Hardens filesystem and runtime behavior around atomic durability, private temporary worktree visibility, claims-off bounded mutation, discard approval, and handoff receipt retention.
- Separates verification ownership into fast, compiled-worker, packaged, and Linux-system lanes.

## Session lifecycle

Parking and resuming sessions are now canonical product actions rather than UI-local behavior. Retention intent is persisted through the registry, execution scope can be recovered from persisted provenance, and the public contract exposes the corresponding v2 actions.

## Runtime observation

Repository observation now composes typed observations for coordination, processes, runtime profiles, filesystem authority, and lifecycle state. Unavailable derived sections remain explicit rather than being silently omitted.

## Architecture and documentation

The repository documentation has been reorganized around the target architecture. Start with `docs/index.md` and `docs/architecture/index.md`; operational/reference material is separated from architecture authority and preserved runtime evidence.

## Compatibility

Node.js 24 or newer remains required. Protected session execution remains Linux-only and fail-closed when required sandbox/runtime capabilities are unavailable.

Existing CLI and terminal workflows remain available. The Control Server remains optional and machine-local.

## Upgrade

```bash
npm install -g nawabari@0.14.0
npx -y nawabari@0.14.0 --version --json
```
