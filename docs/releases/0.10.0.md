# Nawabari 0.10.0

Nawabari 0.10.0 completes the Session Runtime Projection work from Epic #287. Protected session execution now resolves an explicit, deterministic runtime projection instead of inheriting broad host runtime visibility, with strict execution as the default and compatibility available only as an explicit opt-in policy.

## Highlights

- Adds the versioned Session Runtime Projection model for deterministic runtime requirements, filesystem visibility, executable providers, and materialization evidence.
- Makes strict runtime resolution the protected-execution default for `session run` and `session shell`.
- Adds deterministic runtime profiles and resolves the canonical `development` profile through explicit materializer evidence.
- Adds a canonical governed executable surface at `/nawabari/bin` and makes direct execution and PATH-based lookup resolve through the same projection authority.
- Adds interactive `session shell` using the same protected runtime and executable projection used by `session run`.
- Adds bounded Nix runtime-closure materialization without exposing the whole Nix store.
- Adds bounded standalone-Linux/FHS materialization with explicit Node, Git, and pnpm evidence and ELF dependency closure instead of broad `/usr`, `/bin`, `/lib`, or `/lib64` mounts.
- Makes explicit compatibility projection the sole authority for legacy runtime visibility. Compatibility is no longer represented by an omitted projection.
- Adds a pinned tgrep runtime and a projected `rg` provider with a closed compatibility matrix and real-backend conformance coverage.
- Adds deterministic pinned RTK and pnpm backend materialization and a recursion-safe projected `/nawabari/bin/pnpm` middleware path.
- Adds dedicated CI conformance lanes for the pinned tgrep and RTK/pnpm runtime paths.

## Runtime safety and correctness

0.10.0 tightens the runtime boundary around declared artifacts and filesystem identity:

- Filesystem projection compilation rejects overlapping or ambiguous targets and preserves file-vs-directory Landlock semantics.
- Runtime artifacts are inspected through descriptor-backed file identity checks and validated against the final canonical pathname before being accepted into a projection.
- Generated tgrep and pnpm provider artifacts use exclusive creation and fail closed on identity replacement.
- Failure cleanup never unlinks a generated runtime artifact by pathname after an identity check, avoiding a second check/use race against replacement files.
- Generated pnpm middleware reports RTK spawn failure deterministically as exit status `127` without allowing a later child close event to overwrite that result.
- CodeQL findings identified during release hardening were fixed in production code rather than suppressed.

## Compatibility and migration

This release changes the protected-runtime default relative to 0.9.2.

`session run` and `session shell` now select the strict runtime policy by default. Under strict policy, host tools are not visible merely because they exist on the host PATH or under broad system runtime roots. Required runtime material must be represented by the selected deterministic projection and materializer; missing or ambiguous material fails closed.

If an existing workflow intentionally depends on the previous broader host-runtime visibility, invoke the protected command with:

```bash
--runtime-policy compatibility
```

Compatibility mode remains explicit and projection-backed. It does not restore ambient host PATH as an independent authority, and it does not broaden worktree/session write authority.

No persisted-session or registry migration is required. Node.js 24 or newer remains required. Protected execution remains Linux-only and fails closed when required sandbox primitives or runtime material are unavailable.

## Upgrade

```bash
npm install -g nawabari@0.10.0
npx -y nawabari@0.10.0 --version --json
npx -y nawabari@0.10.0 capabilities --json
npx -y nawabari@0.10.0 doctor --json
```

For protected execution, verify the selected runtime policy and readiness before relying on a session workload:

```bash
npx -y nawabari@0.10.0 doctor --json
npx -y nawabari@0.10.0 session run <session-id> -- <command>
```

Use `--runtime-policy compatibility` only for workloads that deliberately require the compatibility projection.

The release path verifies the immutable `v0.10.0` tag against `package.json`, runs format, lint, typecheck, tests, governance validation, package validation, protected runtime conformance, and Node.js 24 packed-artifact smoke tests before npm publication through Trusted Publishing/OIDC.
